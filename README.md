[![NVR CI](https://github.com/saymer-alt/keenetic-nvr/actions/workflows/nvr-ci.yml/badge.svg)](https://github.com/saymer-alt/keenetic-nvr/actions/workflows/nvr-ci.yml)

**Автономный резервный видеорегистратор для Keenetic с Entware.** Забирает RTSP-потоки камер, сохраняет MKV на USB-диск, автоматически восстанавливает отказавшие процессы FFmpeg и сообщает о проблемах через Telegram. Команды Telegram позволяют проверять текущую запись без SSH.

## Два независимых модуля для разных Keenetic

Этот репозиторий содержит два сервиса, которые **не нужно устанавливать вместе**:

- **[NVR/v2](NVR/v2/README.md)** — запись RTSP в MKV, управление архивом, watchdog и Telegram на первом KN-1012. Его мастер — корневой `setup.sh`.
- **[STREAM/v1](STREAM/v1/README.md)** — отдельный RTSP → HTTP MPEG-TS сервер для Selenga и ЭЛТ-телевизора на втором KN-1012. У него собственный `STREAM/v1/bootstrap.sh`, служба `S99stream` и плейлист M3U. **Не записывает MKV, не трогает диски и cron NVR.**

**Удаление NVR v2:** `sh setup.sh remove` (подтверждение `REMOVE`); архив, конфиг и общие пакеты сохраняются. [Подробности удаления](#удаление-knvr-nvr-v2).

**Релизный кандидат v2.5.0-rc.1:** [примечания к выпуску](RELEASE-NOTES-v2.5.0-rc.1.md). Наработки уже находятся в `main`; аппаратно проверены TIME/72h и STREAM. Виртуальные проверки CIRCULAR/HYBRID, RO/unmount/RW recovery, локального fresh-install и reboot/Cron завершены успешно. Для полного релиза `v2.5.0` остаются аппаратные проверки CIRCULAR/HYBRID, физического USB-loss, полного HTTPS-пути `setup.sh` на пустом архивном EXT4 и повторного reboot после Mesh-восстановления ([#7](https://github.com/saymer-alt/keenetic-nvr/issues/7), [#10](https://github.com/saymer-alt/keenetic-nvr/issues/10)).

**Проверено 18.10.2026: чистая Entware на двух KN-1012, установка STREAM штатным bootstrap и ручное восстановление NVR v2.5 на чистой Entware с сохранением существующего MKV-архива (без `setup.sh`/`fresh-install.sh`).** Полное восстановление двух KN-1012 после Mesh-reset подтверждено: STREAM → Selenga → Sony ЭЛТ (3/3), NVR v2.5 → MKV на прежнем архивном EXT4 (3/3 HEALTHY), TIME/72h, удаление 276 просроченных MKV, уведомления и Telegram-команды 4/4 PASS. **[Финальный протокол](FIELD-ACCEPTANCE-2026-10-18.md)**; [первичная инвентаризация](FIELD-RESTORE-2026-10-18.md). ## Кому это нужно и что получится

Если у вас уже есть **RTSP-источник и Keenetic с Entware**, проект превращает роутер в **резервный локальный видеорегистратор** — без обязательного облака и без перекодирования видео. **Ограничение v2.x:** один адрес RTSP-источника и общие учётные данные на набор каналов (например, 101/201/301 одного регистратора). Три независимые IP-камеры с разными адресами и логинами пока не поддерживаются штатным конфигом — [задача #9](https://github.com/saymer-alt/keenetic-nvr/issues/9).

**Путь новичка:**

1. Подключите **отдельный USB-диск с EXT4** под архив (не тот, где установлен Entware) и убедитесь, что камера отдаёт RTSP-поток.
2. Откройте [быстрый старт](#быстрый-старт-новый-keenetic) и запустите интерактивный установщик. Он спросит адрес камеры и параметры диска.
3. После установки убедитесь, что создаются свежие **MKV-файлы** и статус записи здоровый.
4. При желании включите [Telegram-оповещения и команды](#telegram-оповещения-и-статус-из-чата).

`IP-камера → RTSP → Keenetic / FFmpeg → MKV на USB-диске`

**Важно:** штатный режим **TIME + 72 часа** сохраняет сегменты не меньше заданного срока; при переполнении диска запись может пострадать. Режимы CIRCULAR/HYBRID в v2.5 пока **не проходили аппаратную приёмку**. Подробности и различия — ниже.

> **NVR v2.5 — CI PASS; виртуальная приёмка 17/17 PASS (27.10.2026); на реальном KN-1012 частично проверен TIME/72h, включая удаление 276 MKV. Восстановление после reboot и исчезновения FFmpeg (3/3) подтверждено в эксплуатации 13.10.2026. Аппаратные проверки CIRCULAR/HYBRID, физического USB-loss и повторного reboot после Mesh-восстановления остаются открытыми.**
> **NVR v2.4 — аппаратно проверенная базовая установка KN-1012.** Подробности:
> [режимы хранения](NVR/v2/STORAGE-MODES.md).
> Работа на Keenetic KN-1012 подтверждена 10 октября 2026 года. Проверенные и ещё не проверенные сценарии перечислены ниже. Репозиторий выделен из [keenetic-knowledge-base](https://github.com/saymer-alt/keenetic-knowledge-base).

## Реальные сценарии использования

### Домашняя система: три камеры, локальный архив и ЭЛТ-телевизор 1992 года

**Проверено на реальном оборудовании 18.10.2026.** После смены основного роутера и сброса настроек Mesh автор восстановил два независимых сервиса на отдельных **KN-1012**: один записывает видеоархив, второй транслирует изображение с камер на приставку **Selenga 980** и **Sony ЭЛТ 1992 года**. Это пример работающей системы, а не требование использовать сразу два роутера.

```text
                     IP-камеры (RTSP)
                       /         \
     основные потоки 101/201/301   субпотоки 102/202/302
                   |                       |
             KN-1012 №1                KN-1012 №2
                NVR/v2                  STREAM/v1
                   |                       |
            FFmpeg → MKV             FFmpeg → HTTP MPEG-TS
                   |                       |
        отдельный USB-диск EXT4         Selenga 980
          архив и очистка                  |
                                    аналоговый AV-выход
                                          |
                                     Sony ЭЛТ (1992)
```

| Что требуется | Как реализовано в домашней системе | Проверенный результат |
| --- | --- | --- |
| **Записывать три камеры локально** | NVR/v2 копирует основные RTSP-потоки 101/201/301 в MKV на отдельный USB-диск EXT4 | **3/3 HEALTHY**, новые файлы создаются |
| **Смотреть камеры на старом телевизоре** | STREAM/v1 отдаёт субпотоки 102/202/302 в HTTP MPEG-TS (порты 8999/9000/9001), Selenga 980 выводит аналоговый видеосигнал на Sony ЭЛТ | **3/3 STREAM worker UP**, изображение подтверждено |
| **Контролировать архив удалённо** | Watchdog, уведомления Telegram и команды `/status`, `/cameras`, `/disk`, `/help` | **4/4 Telegram-команды PASS** |
| **Очищать старые записи** | Политика **TIME/72h**: удаляются завершённые MKV старше 72 часов, а не самые старые файлы при заполнении диска | **276 MKV удалены вручную 18.10**, +14,9 ГБ; **21.10 архив содержит около 70 часов записей**, что согласуется с последующей очисткой по сроку |

В этой конфигурации **Entware размещён на внутренней UBIFS**, а видеоархив — на отдельном внешнем EXT4. Для снижения износа NAND временные каталоги работают через `tmpfs`. STREAM не сохраняет MKV и не выполняет очистку диска NVR. Для вывода на старую приставку используются совместимые субпотоки, а не основные 2K/H.265-потоки.

**Что важно не перепутать:** в описанном домашнем сценарии проверена *очистка архива по возрасту* (TIME/72h), **не** режим CIRCULAR по заполнению диска. CIRCULAR/HYBRID прошли нативный E2E в эмуляторе 27.10.2026 с реальным EXT4 и давлением на диск; аппаратная приёмка остаётся открытой. Восстановление записи NVR после reboot наблюдалось 13.10.2026, но после Mesh-восстановления 18.10 reboot не повторяли. Для STREAM ещё не подтверждены автозапуск после перезагрузки и длительная непрерывная нагрузка; один HTTP-порт STREAM обслуживает одного клиента одновременно.

**Подробнее:** [полевой протокол 18.10.2026](FIELD-ACCEPTANCE-2026-10-18.md) · [восстановление после Mesh-reset](FIELD-RESTORE-2026-10-18.md) · [установка NVR](NVR/v2/README.md) · [настройка STREAM](STREAM/v1/README.md) · [проверенный плейлист Selenga/Sony](STREAM/v1/playlist/selenga-sony-1992.m3u).

## Режимы хранения (v2.5 candidate)

| Режим | Правило | Для кого |
| --- | --- | --- |
| **TIME** | 24 / 72 / 168 / 336 часов или своё значение; **никогда не удалять раньше срока** | Гарантированный период хранения |
| **CIRCULAR** | По заполнению диска, самые старые завершённые MKV удаляются первыми | Максимальная доступная глубина архива |
| **HYBRID** | Удаление по сроку и раньше при нехватке места | Баланс между возрастом и пространством |

По умолчанию остаётся **TIME + 72 часа**, включая обновления со старых
конфигураций. Режимы CIRCULAR/HYBRID требуют отдельного подтверждения
безвозвратного досрочного удаления. Режим TIME/72h испытан на реально работающем KN-1012 с существующим архивом, включая preview и удаление истёкших сегментов; CIRCULAR/HYBRID не испытаны на тестовом USB. [Подробнее о гарантиях и настройках](NVR/v2/STORAGE-MODES.md).

## Возможности

- **RTSP → MKV без перекодирования** (`ffmpeg -c copy`). Сегменты примерно по 15 минут, нарезка зависит от ключевых кадров.
- **TIME/72h:** завершённые MKV не удаляются *раньше* 72 часов после их `mtime`. Это политика удаления, **не гарантия 72 часов непрерывного видео**: при недоступности камеры или заполнении диска возможны пробелы. Режим не удаляет свежие файлы даже при нехватке места.
- **Watchdog** раз в 5 минут: проверяет процессы и свежесть файлов каждого канала, перезапускает проблемную камеру с задержкой повторов.
- **Статус и журнал**: `HEALTHY`, `DEGRADED`, `PAUSED`, `NO-DISK`; диск, последнее обновление видео, очистка и ошибки.
- **Telegram-оповещения** о сбоях камер, недоступности накопителя, ошибках очистки, заполнении и восстановлении. Дополнительно — HTTPS webhook.
- **Telegram по запросу** (`/status`, `/cameras`, `/disk`, `/help`): отдельный модуль только для чтения, принимает команды лишь из настроенного приватного чата.
- **Установка и резервные копии:** для нового устройства есть мастер. Проверен управляемый upgrade **v2.3 → v2.4** с откатом; **upgrade v2.4 → v2.5 ещё не реализован**, не применять старый скрипт для него ([#13](https://github.com/saymer-alt/keenetic-nvr/issues/13)). Секреты остаются локально на роутере.

| Полная установка NVR одной командой `setup.sh` на пустом тестовом EXT4 | **Ещё не проверено**; это отдельный тест установщика, не работы NVR |
| Фактический rollback установщика NVR | **Ещё не проверено** |

Автоматическая очистка с `REMOVED FILES: 0` (10.10) подтверждала запуск Cron, а **реальное удаление 276 MKV** отдельно подтверждено вручную 18.10 после успешного dry-run. Снимки 21.10 показывают архив примерно за 70 часов — **косвенное подтверждение периодического удержания TIME/72h**; для строгого подтверждения конкретного автоматического запуска HH:03 требуется `LAST CLEANUP`/журнал Cron. Офлайн-тесты входят в CI. Полный журнал: [CHANGELOG](NVR/v2/CHANGELOG.md); ограничения: [KNOWN-LIMITATIONS](NVR/v2/KNOWN-LIMITATIONS.md).

## Безопасность NAND и восстановление после Mesh

Для двух домашних KN-1012 Entware планируется на внутренней **UBIFS**.
Поэтому постоянными во внутренней памяти остаются только пакеты,
база OPKG и конфигурация, а высокочастотные записи разделены:
NVR: PID/lock/check/sort в проверенный RAM `/tmp`, MKV/FFmpeg-логи
и долговременный Telegram offset — на внешнем EXT4;
STREAM: временные PID/lock в RAM `/tmp`, FFmpeg выводит HTTP MPEG-TS,
не создавая архивов.
Оба сервиса отказываются работать, если `/tmp` не подтверждён как tmpfs.
Установка проверяет файловую систему и отказывает при обнаружении старых MKV.
Для Entware `/opt/tmp`, `/opt/var/log`, `/opt/var/run`
оба установщика при внутреннем /opt автоматически устанавливают
или активируют **оригинальную `S00ubifs` из KAS/stable** через общий
защитный модуль; три действующих tmpfs обязательны.
Установщики не форматируют диски, не запускают Mihomo/KAS целиком
и не меняют swap. Предпроверка остаётся read-only.
**Безопасный аудит без изменений:** [tools/nand-audit.sh](tools/nand-audit.sh).
Подробности: [NAND-WEAR.md](NAND-WEAR.md). **Сохранившийся архив не является пустым диском** — не запускайте
`setup.sh install` поверх него. Порядок действий: [MESH-RECOVERY.md](NVR/v2/MESH-RECOVERY.md).
Аппаратная приёмка новой защиты ещё не завершена.

## Быстрый старт (новый Keenetic)

Нужны Keenetic с Entware, отдельный USB-диск **EXT4** под видеоархив (не системный диск Entware), доступ к RTSP и пакеты `ffmpeg`, `cron`, `curl`, `coreutils-stat`. Интерактивный установщик поможет поставить недостающие пакеты.

На **новом** роутере с уже установленным Entware, подключённым отдельным
USB-диском EXT4 и открытым интерактивным SSH-терминалом запустите **одну команду**:

```sh
opkg update && opkg install curl && \
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/setup.sh | sh
```

Это запускает **полную установку**, а не только preflight:
загрузчик проверит Entware, предложит установить недостающие
`ffmpeg`, `cron` и `coreutils-stat`, затем мастер спросит диск,
RTSP IP/логин/пароль (ввод скрыт), каналы, необязательные уведомления
и убедится, что появился свежий MKV каждой камеры. После проверки
добавятся задания Cron. Архивный диск не должен совпадать с диском Entware.

**Вариант с проверкой успешности скачивания `curl` и без передачи сети напрямую в shell**
(предпочтителен при нестабильном подключении):

```sh
opkg update && opkg install curl && \
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/setup.sh \
  -o /tmp/keenetic-nvr-setup.sh && \
sh -n /tmp/keenetic-nvr-setup.sh && sh /tmp/keenetic-nvr-setup.sh
```

Только предварительная проверка (может предложить доустановить пакеты):

```sh
sh /tmp/keenetic-nvr-setup.sh preflight
```

Последняя команда предполагает, что вы скачали файл вторым способом.

Установщик запросит параметры через `/dev/tty`, поэтому работает и
при `curl | sh`. Для **уже установленной** NVR повторная установка
блокируется намеренно. Отдельный сценарий обновления существует только
для v2.3 → v2.4; обновление v2.4 → v2.5 пока **не реализовано** — рабочую
v2.4 не обновляйте до появления проверенного upgrade-сценария с откатом
(issue #13). Конфигурация: `/opt/etc/nvr-v2.conf`, права `600`.

**Закрепление версии (воспроизводимость).** Ссылки установки по умолчанию
указывают на ветку `main`, чтобы уже опубликованные команды не ломались.
Для повторяемой установки в точности той же версии задайте базу raw-ссылок
на фиксированный коммит или (после выпуска) тег:

```sh
NVR_RAW_BASE='https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/<тег>/NVR/v2' \
  sh /tmp/keenetic-nvr-setup.sh
```

Аналогичные переопределения есть у загрузчиков: `NVR_PROJECT_RAW_BASE`
(корень репозитория, модуль NVR), `NVR_BOT_RAW_BASE` (Telegram-установщик),
`STREAM_PROJECT_RAW_BASE`/`STREAM_RAW_BASE` (STREAM), а исходный `S00ubifs`
всегда берётся из неизменённого оригинала `keenetic-auto-setup/stable`
(переопределение `KNVR_KAS_S00_URL` — только для тестов).

**Штатная чистая установка NVR через `setup.sh` на пустой архивный диск ещё не подтверждена**:
офлайн-тесты в CI не заменяют эту проверку.

### Обновление действующей v2.3

Для устройства **со старой v2.3**, не для чистой установки:

```sh
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/NVR/v2/bootstrap.sh -o /tmp/nvr-upgrade.sh
sh /tmp/nvr-upgrade.sh preflight-upgrade
```

После `Upgrade preflight PASS`:

```sh
sh /tmp/nvr-upgrade.sh upgrade
```

Установщик временно останавливает резервную запись, проверяет её возобновление и восстанавливает Cron. Резервная копия и инструмент отката находятся в `/opt/etc/nvr-v24-upgrade-backup/`. **Уже работающую v2.4 повторно обновлять этим сценарием не нужно.**

## Telegram: оповещения и статус из чата

Для нового бота создать API-токен через [@BotFather](https://t.me/BotFather), открыть чат с созданным ботом, отправить `/start` и сообщение.

Подключение оповещений к **уже установленной NVR v2.4/v2.5**:

```sh
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/NVR/v2/telegram-setup.sh -o /tmp/nvr-telegram-setup.sh
sh -n /tmp/nvr-telegram-setup.sh && sh /tmp/nvr-telegram-setup.sh
```

Для интерактивных запросов статуса: `opkg install jq` и опциональный cron-поллер.

```sh
opkg update && opkg install jq
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/NVR/v2/telegram-bot-install.sh -o /tmp/nvr-telegram-bot-install.sh
sh /tmp/nvr-telegram-bot-install.sh preflight
sh /tmp/nvr-telegram-bot-install.sh install
```

После этого отправляйте боту `/status`, `/cameras`, `/disk` или `/help`. Ответ приходит обычно в течение минуты (опрос Bot API по Cron). **Бот не может останавливать запись или удалять архив.** Токен хранится только в приватном конфиге роутера, вводить повторно для модуля команд его не нужно.

## Совместимость и безопасность

Старые файлы в `keenetic-knowledge-base/NVR/v2/` сохранены для совместимости уже опубликованных команд. **Новый основной адрес проекта — `saymer-alt/keenetic-nvr`.** Существующие роутеры не требуется перенастраивать только ради переноса кода в GitHub.

Никогда не публикуйте содержимое `/opt/etc/nvr-v2.conf`, токены Telegram, RTSP-пароли, полные выводы `ps` или видеоархивы. RTSP URL может быть виден локально в параметрах процесса FFmpeg; выделенная RTSP-учётная запись рекомендуется.

## Удаление KNVR (NVR v2)

```sh
curl -fsSL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/setup.sh | sh -s -- remove
```

Введите `REMOVE`. Для локально скачанного репозитория: `sh uninstall.sh`
(или `sh uninstall.sh --yes` для намеренного запуска без вопроса).
Удаление отключает задания NVR/Telegram в cron, останавливает запись и удаляет
три программных файла NVR v2. **Видеоархив, конфиг `/opt/etc/nvr-v2.conf`, offset
Telegram, резервные копии, STREAM, Entware, FFmpeg, Cron и S00ubifs сохраняются.**
Повторный запуск допустим. При `PARTIAL` устраните указанную причину и повторите
команду; оставшиеся программные файлы сохраняются для диагностики и остановки.
Ручные shell-обёртки/нестандартные задания cron и legacy v1 требуют ручной проверки.

Для повторной установки с сохранённым конфигом используйте
`sh NVR/v2/bootstrap.sh install-fresh` из скачанного репозитория. Обычный
`setup.sh install` намеренно отказывается перезаписывать существующий конфиг.

Результаты виртуальной проверки: [KNVR в Router Emulator](docs/testing/KNVR-EMULATOR-2026-10-27.md).
