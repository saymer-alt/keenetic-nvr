# STREAM/v1 — автономная трансляция камер на Selenga и ЭЛТ Sony

**Отдельный модуль** репозитория [keenetic-nvr](https://github.com/saymer-alt/keenetic-nvr).
Рассчитан на **Keenetic KN-1012 с Entware** и IPTV-приставку Selenga с аналоговым видеовыходом. Целевое устройство пользователя: второй KN-1012 (`192.168.1.3`). Рабочий NVR/архив — отдельный KN-1012 (`192.168.1.2`).

```text
IP-камеры / RTSP
       |
       v
KN-1012 (только STREAM/v1, FFmpeg)
       |
       +--> http://192.168.1.3:8081 -- Camera 101
       +--> http://192.168.1.3:8082 -- Camera 201
       +--> http://192.168.1.3:8083 -- Camera 301
       |
       v
Selenga 980 (IPTV/M3U) --> AV-выход --> ЭЛТ Sony
```

## Entware на внутренней NAND

Для обоих домашних KN-1012 выбран профиль `/opt` на внутренней UBIFS.
STREAM не записывает видео на накопители. Все PID/lock и временные
файлы идут в `/tmp`; запуск теперь **останавливается**, если фактическая
точка монтирования `/tmp` не является RAM `tmpfs` или путь состояния
уводит по символической ссылке в NAND. FFmpeg выдаёт HTTP MPEG-TS,
выход процесса перенаправлен в `/dev/null`, без постоянных логов.

За пределами самого STREAM необходимо дополнительно проверить системные
временные каталоги Entware (особенно `/opt/var/log`). Чек-лист:
[защита NAND на обоих роутерах](../../NAND-WEAR.md).
**Установщик STREAM автоматически подключает оригинальную `S00ubifs`**
из KAS/stable при внутреннем /opt до записи STREAM-файлов.
Активный сервис не меняется, неактивный запускается, отсутствующий
скачивается и проверяется; нужен PASS на трёх tmpfs.
`preflight` остаётся read-only. При других работающих службах Entware
сначала проверьте `/opt/var/log` и `/opt/var/run`: исходная KAS
S00ubifs накрывает эти каталоги tmpfs, не переносит их файлы.

## Почему это отдельный модуль

| Назначение | NVR/v2 | STREAM/v1 |
| --- | --- | --- |
| Keenetic | Первый KN-1012 | Второй KN-1012 |
| Результат | MKV на отдельном EXT4-диске | HTTP MPEG-TS на LAN-портах |
| Работа FFmpeg | Копирование RTSP в MKV-сегменты | Копирование видео, G.711 → AAC |
| Автозапуск | Скрипты NVR и cron | Только `S99stream` |
| Диск/очистка | Политики TIME/CIRCULAR/HYBRID | Не использует диск, не удаляет файлы |
| Память | Проверки NAND и архивного диска | PID/lock только в `/tmp` |

**Не запускайте корневой `setup.sh` ради трансляции:** он предназначен для NVR. `STREAM/v1` не требует `cron`, `findutils`, отдельного диска под видео, `fsck` или 300-секундного ожидания монтирования. Проверка длительного `fsck` относится к записи архива, а не к сетевому вещанию.

## Установка — только на STREAM-роутере

1. Восстановите/подключите Entware на втором KN-1012. Убедитесь, что `/opt/bin/opkg` доступен. Не форматируйте накопитель, если на нём сохранились другие данные.
2. Для трансляции требуется **FFmpeg с поддержкой RTSP и встроенного HTTP-сервера**. Если FFmpeg отсутствует: `opkg update && opkg install ffmpeg`. Других обязательных Entware-пакетов у модуля нет.
3. Скачайте загрузчик, проверьте, затем запустите установку:

```sh
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/STREAM/v1/bootstrap.sh \
  -o /tmp/keenetic-stream-bootstrap.sh
sh -n /tmp/keenetic-stream-bootstrap.sh
sh /tmp/keenetic-stream-bootstrap.sh preflight
sh /tmp/keenetic-stream-bootstrap.sh install
```

Этот модуль доступен из ветки `main`. Загрузчик скачивает `stream.sh`, `install.sh`, `init.d/S99stream`, шаблон конфигурации и проверяет синтаксис до установки. **Он не устанавливает пакеты и не запускает трансляцию автоматически.**

Если на устройстве **уже есть старый `/opt/etc/init.d/S99stream`**, установщик откажется заменять его без подтверждения. Сохраните старый конфиг и проверьте отличия; затем для осознанной замены используйте `STREAM_REPLACE_LEGACY=1 sh /tmp/keenetic-stream-bootstrap.sh install`. Старая версия сохраняется в `/opt/etc/keenetic-stream-backups/`. Новый конфиг **не перезаписывает существующий**.

## Настройка

Измените локальный `/opt/etc/keenetic-stream.conf` (права 600):

```sh
STREAM_RTSP_HOST='192.168.1.135'
STREAM_RTSP_PORT=554
STREAM_RTSP_USER='YOUR_RTSP_USER'
STREAM_RTSP_PASSWORD='YOUR_RTSP_PASSWORD'
STREAM_BIND='192.168.1.3'
STREAM_PLAYLIST_HOST='192.168.1.3'
STREAM_CHANNELS='101:8081 201:8082 301:8083'
STREAM_RESTART_DELAY=2
```

Логин и пароль **только в локальном конфиге**, никогда в GitHub, issue, плейлисте или Telegram. Если пароль когда-либо был опубликован в чате/публичном руководстве — замените его на камере. Приложение не публикует RTSP URL в stdout, однако FFmpeg получает URL аргументом процесса: локальный администратор роутера потенциально может увидеть пароль в `/proc`. Для потоков заведите отдельного пользователя камеры с минимальными правами и ограничьте доступ к SSH.

В старом прототипе использовались разные порты, например `8999/9000/9001`. Их можно указать через `STREAM_CHANNELS`; для нового развёртывания предусмотрены `8081/8082/8083`. Для маломощной Selenga и ЭЛТ рекомендуется попробовать субпотоки `102/202/302` с **H.264** и низким разрешением. `-c:v copy` не переводит H.265 в H.264: если приставка не декодирует H.265, необходимо переключить источник или отдельно разработать режим транскодирования.

## Управление

```sh
sh /opt/etc/keenetic-stream.sh check
sh /opt/etc/keenetic-stream.sh start
sh /opt/etc/keenetic-stream.sh status
sh /opt/etc/keenetic-stream.sh playlist > /tmp/cctv.m3u
sh /opt/etc/keenetic-stream.sh stop
sh /opt/etc/keenetic-stream.sh restart
```

Полученный `/tmp/cctv.m3u` можно скопировать на флешку для Selenga. Готовый пример: [playlist/cctv.m3u.example](playlist/cctv.m3u.example). При смене IP/портов **лучше формировать плейлист командой `playlist` из актуального конфига**.

`S99stream` автоматически поднимет трансляцию вместе с Entware при следующей загрузке, после корректной настройки. Пример синхронной проверки HTTP после старта: откройте ссылку в VLC либо непосредственно на приставке. Сервис на основе `ffmpeg -listen 1` обслуживает **одного HTTP-клиента на порт**; отключение/переключение Selenga завершает FFmpeg, watchdog перезапускает *только* соответствующий канал через 2 секунды. Сервис сохраняет PID в RAM и не запускает системный `pkill`, который мог бы остановить чужую запись MKV.

**Ограничение:** схема с `-listen 1` не рассчитана на несколько одновременных зрителей одной камеры; также возможно, что новая версия FFmpeg или конкретная модель приставки потребует адаптации. Аппаратную приёмку новой реализации ещё не проводили.

## Разобранные проблемы старой реализации

- **FFmpeg 6.1.4:** флаг `-stimeout` более не используется. Оставлен `-rtsp_transport tcp`; `-timeout` можно включать лишь после проверки конкретной сборки.
- **Время/звук для IPTV:** `-fflags +genpts`, `-map 0:a:0?`, `-c:a aac -b:a 64k -ar 44100` и `-mpegts_flags +resend_headers`. Если камера не отдаёт звук, необязательный аудиоканал не блокирует запуск.
- **Обрыв соединения:** отдельный worker на камеру без глобальных `pkill -9` и без частой записи логов на внутреннюю NAND.
- **`fsck` 1–4 минуты и отсутствие USB:** важно для дискового NVR, который должен проверять *факт монтирования* и не создавать каталоги на неподключённом диске. STREAM не создаёт ни MKV, ни каталогов на `/tmp/mnt`.
- **Cron и `find -mtime +3 -delete`:** оставлены исключительно NVR. В Entware правильный способ редактирования пользовательских заданий — `crontab -e` или аккуратное добавление через `crontab -l`; **никогда не переписывайте** чужие задания и системный `/opt/etc/crontab` целиком.
- **Потеря Entware после переподключения к Mesh:** прежде всего проверьте старую привязку `opkg disk` и существующие файлы. Не переустанавливайте поверх носителя вслепую.

## Проверки перед вводом в эксплуатацию

CI: [`tests/stream-service.sh`](../../tests/stream-service.sh) — три канала, выдача M3U, повторный start, рестарт после обрыва, избирательный stop, отказ на неправильном конфиге и отсутствие воздействия на чужие PID. Для железа необходимо дополнительно проверить реальное декодирование MPEG-TS приставкой Selenga, правильный кодек субпотока, открытие/закрытие одного HTTP-клиента, работу после перезагрузки и отсутствие неожиданных нагрузок.
