# Решение: выделить Keenetic NVR в отдельный репозиторий

**Дата решения:** 2026-10-10  
**Статус:** предложение одобрено для подготовки; сам перенос ещё НЕ выполнялся.  
**Текущее расположение:** `saymer-alt/keenetic-knowledge-base/NVR/v2/`  
**Предлагаемое название:** `saymer-alt/keenetic-nvr` (проверить доступность перед созданием).

## Почему проекту нужен свой репозиторий

Начавшись как практическая инструкция, NVR вырос в независимое приложение для
Keenetic + Entware:

- FFmpeg RTSP stream copy в MKV-сегменты по ~15 минут;
- watchdog по Cron и независимое восстановление камер;
- минимальная глубина архива **72 часа на каждую камеру**;
- контроль свободного места и успешности очистки, без удаления свежих файлов ради места;
- Telegram / HTTPS webhook аварийные уведомления;
- приватные read-only Telegram-команды `/status`, `/cameras`, `/disk`, `/help`;
- установщики, обновление с резервной копией и откатом, тесты BusyBox ash, CI, документация.

Раздельный репозиторий упростит Issues, релизы, теги, CI и независимую установку.
В базе знаний останется описание сценария и указатель на приложение.

## Что переносить

Из `NVR/v2/`: `nvr.sh`, `bootstrap.sh`, `install-router.sh`,
`upgrade-router.sh`, `fresh-install.sh`, `telegram-setup.sh`,
`telegram-bot.sh`, `telegram-bot-install.sh`, пример конфига,
`README.md`, `ARCHITECTURE.md`, `CHANGELOG.md`,
`KNOWN-LIMITATIONS.md` и прочие относящиеся к v2 файлы.

Из `tests/`: только тесты NVR и требуемые ими фикстуры
(включая FFmpeg stub, retention, Telegram, уведомления и проверку секретов).

Из `.github/workflows/`: отдельный workflow для NVR с поправкой путей.
Уточнить `.gitattributes`, `LICENSE` (MIT) и связанные документы.

**Не переносить автоматически** старую часть `NVR/` про HTTP-streaming,
скрипты v1, либо прочие материалы общей базы знаний. Сохранить там
историческую инструкцию и отдельный миграционный указатель.

## Порядок без простоя домашнего NVR

1. Создать *новый* репозиторий `saymer-alt/keenetic-nvr` с `main`
   (отдельное согласование и проверка имени). Исходный репозиторий не удалять.
2. По возможности перенести git-историю путей через `git filter-repo`
   или `git subtree split`; если это невозможно, импортировать с записью
   исходного commit SHA и ссылки на PR #3/#7.
3. Разложить `NVR/v2/` как корень нового репозитория, перенести тесты,
   настроить GitHub Actions, ShellCheck и scan секретов. Никаких настоящих
   RTSP-паролей, Bot API token, Chat ID, `nvr-v2.conf` и артефактов с USB.
4. Исправить **все абсолютные URL** в `bootstrap.sh`,
   `telegram-bot-install.sh`, README, примерах curl и других установщиках;
   тестами проверить, что новый установщик скачивает файлы из **нового repo**.
5. Запустить CI в новом репозитории, сверить файлы с проверенным кодом
   старого main; выпустить версионный тег после контрольного теста.
6. Оставить текущие `NVR/v2/` и старые raw.githubusercontent.com-ссылки
   работоспособными на переходный период. Не удалять файлы, от которых
   зависят уже установленные роутеры; старый README пометить как
   «перенесено, новый upstream ...». Позднее при необходимости добавить
   простые совместимые redirect/bootstrap wrappers после тестов.
7. Перевести дальнейшие Issues/PR/релизы в новый репозиторий, а в базе
   знаний оставить короткую актуальную статью со ссылкой на проект.
8. В отдельном, согласованном окне обновить рабочие роутеры **только если
   появится техническая необходимость**. Запись FFmpeg, локальные cron,
   файлы `/opt/etc/nvr-v2.conf` и USB-архивы при переносе GitHub менять
   **не нужно**.

## Критерии завершения

- Новый публичный README на русском; компоненты, пакеты и права расписаны.
- Установка на новом Keenetic из нового repo проходит preflight/smoke.
- Обновление, Telegram setup и command-bot не ссылаются на старый upstream.
- CI зелёный; raw URL и совместимость проверены.
- Старые ссылки и запущенный KN-1012 не сломаны, архив 72 часа не затронут.
- В старом `keenetic-knowledge-base` остался понятный migration notice.
- Непроверенные реальные сценарии остаются в Issues/backlog.

## Решение до переноса

**До создания нового репозитория источником истины остаётся текущий
`saymer-alt/keenetic-knowledge-base` (ветка `main`).**
Не вести параллельно две изменяемые версии NVR. Никаких автоматических
переездов и изменений на домашнем роутере только из-за этого документа.
