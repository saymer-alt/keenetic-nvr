# NVR v2 — changelog

## 2.4 (2026-10-09, candidate)

Production hardening поверх v2.3. Все изменения покрыты офлайн-тестами
(5 сюит: smoke, retention-матрица 12 кейсов, логика уведомлений, хелперы
установщика, сканер секретов) и CI (GitHub Actions: синтаксис sh+ash,
ShellCheck, тесты, скан секретов).

### Добавлено

- **Состояние очистки и проверки** (`LAST CLEANUP`, `LAST SUCCESSFUL CLEANUP`,
  `CLEANUP RESULT` OK/PARTIAL/FAILED/NEVER, `REMOVED FILES`, `LAST CHECK`) —
  пишется атомарно в `/tmp` и на архивный диск (переживает перезагрузку).
  Успешная очистка с нулём удалённых файлов — норма (`OK`), а не ошибка.
- **Богатый `status`**: заголовок HEALTHY/PAUSED/NO-DISK, диск (занято %,
  свободно ГБ), RETENTION/SEGMENT, состояние каждой камеры
  (HEALTHY/STARTING/STALE/DOWN/STOPPED/UNKNOWN) и возраст последней записи,
  `ALERTS: enabled|disabled`.
- **Уведомления (необязательный модуль)**: Telegram Bot API и/или HTTPS
  webhook; события 75%/90%, камера не пишет, watchdog не смог восстановить,
  RECOVERY, носитель недоступен/read-only (CRITICAL), очистка застряла (WARN),
  прогноз свободного места на 72 часа (WARN, только при наличии данных).
  Дедупликация по инциденту с интервалом повторов; RECOVERY только после
  подтверждённого восстановления; `nvr notify test`; токены — в конфиге 600,
  в curl передаются через stdin-конфиг (не видны в `ps`/логах).
- **Команды**: `pause`/`resume`, `logs [N|cam<ID>]`, `notify test`.
- **Долгая остановка**: `stop`/`pause` теперь переживает cron-тики и
  перезагрузку (маркер на архивном диске); `start`/`resume` снимает.
- **Прогноз свободного места** на горизонте 72 часов по фактическому битрейту
  последнего часа записи; без надёжных данных прогноз не строится.
- **Ротация журналов**: events.log (обе копии) ограничен 512 КиБ с сохранением
  хвоста; хвост пропускается через редактирование RTSP-креденшелов.
- **Редактирование секретов в логах**: `nvr logs` и ротация заменяют
  `rtsp://user:pass@` → `rtsp://[REDACTED]@`.
- **Установщик fresh**: автоустановка недостающих пакетов Entware (ffmpeg,
  cron, curl, coreutils-stat) с подтверждением; выбор диска нумерованным
  списком из реально смонтированных RW; отказ выбирать диск, на котором живёт
  `/opt`; скрытый ввод токена Telegram и webhook; live-проверка RTSP с
  процент-кодированием креденшелов (`NVR_RTSP_ENCODE`), если пароль содержит
  URL-спецсимволы; остановка незапущенной записи при неудачной верификации.
- **CI**: `.github/workflows/nvr-ci.yml` (синтаксис, ShellCheck, 5 сюит,
  сканер секретов) и `.gitattributes` (LF для sh/yml/c/example).
- Документация: README переписан (v2.4), добавлены ARCHITECTURE.md,
  CHANGELOG.md, KNOWN-LIMITATIONS.md.

### Исправлено

- **Совпадение каналов**: проверка процесса `owned()` матчитла `/Streaming/Channels/101`
  как подстроку, включая URL канала 1011; совпадение теперь заякорено к концу
  cmdline-элемента.
- **README v2.3 был повреждён** (внутрь файла попала копия самого документа);
  переписан.
- **Автозапуск после `stop`**: cron через ≤5 минут перезапускал остановленные
  камеры; теперь `stop` устанавливает долговременную паузу.
- `resume` больше не блокируется задержкой повторов камеры.
- Ошибка одной очистки больше не обнуляет `LAST SUCCESSFUL CLEANUP`.
- Состояние камер при `STOPPED`/паузе отображается корректно, а не `DOWN`.
- Парсинг статуса установщиками переведён на новый формат CAM-строк.

### Изменено

- Файлы состояния парсятся белым списком ключей с валидацией форматов вместо
  `source` — подмена state-файла на USB не даёт выполнения команд.
- Timestamps в state-файлах хранятся без кавычек (упрощает валидацию).
- `bootstrap.sh` по умолчанию загружает ветку `main` (переопределение —
  `NVR_RAW_BASE`).
- FFmpeg-лог ротация обобщена (`rotate_log`), применяется и к events.log.

## 2.3 (2026-10-09)

Первый рабочий кандидат на KN-1012: безопасный cutover с бэкапом и
автооткатом (`install-router.sh`), извлечение RTSP-параметров локально,
preflight c проверкой `stat`/FFmpeg `-timeout`, интерактивная установка на
новом роутере (`fresh-install.sh`) со скрытым вводом пароля, разделение
cleanup на 3-ю минуту часа. Подтверждено live: три камеры пишут MKV, cron
health-check выполняется по расписанию, процессы не перезапускаются зря.

## 2.0–2.2

Ранние итерации кандидата (см. историю PR #3): переход с v1-скриптов на
конфиг + единый `nvr.sh`, отказ от PID-only watchdog в пользу проверки
свежести файла, границы хранения по mtime.
