# Защита внутренней UBIFS на двух Keenetic KN-1012

Целевая домашняя архитектура (18.10.2026): **Entware хранится во внутренней
постоянной UBIFS на обоих роутерах**, но обе службы обязаны исключать частые
записи в NAND. Не устанавливайте «RAM-диск вместо /opt»: программы и настройки
должны переживать перезагрузку.

| Где | Первый KN-1012 (NVR) | Второй KN-1012 (STREAM) |
| --- | --- | --- |
| Постоянный `/opt` | Внутренняя UBIFS: FFmpeg, cron, jq, настройки | Внутренняя UBIFS: FFmpeg, STREAM, настройки |
| PID/lock/краткосрочная диагностика | `/tmp/nvr-v2` (tmpfs) | `/tmp/keenetic-stream` (tmpfs) |
| Видеоданные | Только проверенный внешний USB EXT4 (`cctv/`) | Нет файлов, HTTP MPEG-TS в локальную сеть |
| Логи FFmpeg | Только внешний USB EXT4, ограниченный размер | `/dev/null`, фоновых файлов нет |
| Telegram poll (раз в минуту) | `<EXT4>/cctv/.nvr-v2/telegram`; offset переживает reboot | Не установлен и не нужен |
| Действия `opkg install` и настройка | Редкие допустимые записи в UBIFS | Редкие допустимые записи в UBIFS |
| Системные временные каталоги Entware | Проверить `/opt/tmp`, `/opt/var/log`, `/opt/var/run` | Те же проверки |

## Проверка без записи в NAND

Одна и та же последовательность выполняется отдельно на **каждом**
KN-1012 после включения Entware. Загрузка идёт во временный каталог
`/tmp`, а не в `/opt`.

```sh
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-nvr/main/tools/nand-audit.sh \
  -o /tmp/keenetic-nand-audit.sh
sh -n /tmp/keenetic-nand-audit.sh
sh /tmp/keenetic-nand-audit.sh
```

Проверки read-only: фактическая файловая система `/opt`, смонтированный
`/tmp` типа `tmpfs`, а также `/opt/tmp`, `/opt/var/log`,
`/opt/var/run`, `/opt/var/cache`, `/opt/var/lib`.
Предупреждение `WARN` на каталоге означает **потенциальный риск**,
а не доказательство постоянных записей. Скрипт не подключается к
камерам и не показывает пароли/токены.

Если `/tmp` не является проверенным RAM-tmpfs, службы NVR и STREAM
будут **отказываться запускаться**, вместо записи временного состояния
во внутреннюю флешку.

## Системные логи Entware

Поскольку сам `opkg` и сторонние Entware-пакеты могут сохранять логи,
одних исправлений NVR/STREAM **недостаточно для защиты всего Entware**.

В [keenetic-auto-setup](https://github.com/saymer-alt/keenetic-auto-setup)
уже есть отдельная служба
[`S00ubifs`](https://github.com/saymer-alt/keenetic-auto-setup/blob/main/S00ubifs)
и [документация](https://github.com/saymer-alt/keenetic-auto-setup/blob/main/docs/06-s00ubifs.md):
она может направлять `/opt/tmp`, `/opt/var/log`,
`/opt/var/run` в RAM с учётом размера доступной памяти.
**Не устанавливать автоматически из NVR или STREAM**, не монтировать
поверх существующих работающих каталогов и не запускать её поверх
непроверенного Entware. На обоих KN-1012 сначала необходимо
прочитать исходную конфигурацию, проверить монтирования и наличие
других сервисов (в том числе DLNA/Transmission). После этого отдельно
решить, требуется ли S00ubifs и как сохранить уже существующие данные.

Нельзя направлять логирование, кеш или swap во внутреннюю UBIFS.
Подкачка должна быть отключена либо использовать поддерживаемую
RAM-зRAM / отдельный внешний накопитель согласно конкретному
профилю памяти (не применять одну схему вслепую на разных моделях).

## Ограничения

- **NAND не становится read-only.** Периодические обновления
  пакетов/конфигурации, базы OPKG и другие службы KeeneticOS по-прежнему
  могут обращаться к постоянной памяти.
- При пропадании внешнего HDD NVR прекращает запись и подтверждение
  новых Telegram-команд. STREAM не зависит от HDD.
- Программы сохраняют пароль RTSP только локально. Не копировать
  `/opt/etc/*.conf` с секретами в GitHub или логи диагностики.
- После замены Mesh-контроллера сначала проверять `opkg disk` и
  старые файлы. Команда привязки может запускать распаковку архивов
  из `/opt/install`: ни привязка, ни переустановка Entware не должны
  выполняться автоматически без проверки носителя.
- Полная аппаратная проверка NAND, tmpfs и USB-loss на обоих роутерах
  остаётся отдельной задачей; CI проверяет алгоритмы на фиктивных mounts.
