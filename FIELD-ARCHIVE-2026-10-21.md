# Полевая проверка видеоархива TIME/72h — 21.10.2026

Дополнение к [приёмке от 18.10.2026](FIELD-ACCEPTANCE-2026-10-18.md). Основание: четыре скриншота Windows Explorer, показанные владельцем 21.10.2026 (доступ к архивному USB EXT4 по локальной SMB-сети). Изображения, адреса устройств, пароли, RTSP URL и MKV в GitHub не публикуются.

## Наблюдение

| Показатель | Значение / источник |
| --- | --- |
| Действующая система | NVR/v2.5, три канала: 101/201/301, режим TIME/72h |
| Папки архива | `cam101`, `cam201`, `cam301` |
| `cam101` | **280 файлов MKV**, Windows показывает **18,5 ГБ** (19 941 718 204 байта) |
| Все три папки | **840 файлов, 3 папки**, Windows показывает **46,0 ГБ** (49 408 309 369 байт) |
| Количество на камеру | По сообщению владельца, **примерно 280 MKV в каждой** папке |
| Имена первых видимых записей `cam101` | `cam101_2026-10-18_21-57-31.mkv` и последующие сегменты каждые ~15 минут |
| Время просмотра | 21.10.2026 около 19:35 по времени ПК (даты папок) |
| Расчётная глубина | **280 × 15 минут ≈ 70 часов** на камеру, что согласуется с TIME/72h |

Значение **46,0 ГБ** приведено по интерфейсу Windows (его отображение использует двоичные единицы); суммарный размер в байтах дан точно, округлённая величина — около **46,0 ГиБ**. Количество файлов и их объём не гарантируют непрерывность видеоряда внутри каждого MKV: для точной оценки нужна выборочная проверка `ffprobe`.

## Итог и уровень уверенности

- **PASS — фактическая запись и наличие сегментов:** спустя три дня после восстановления в трёх каталогах есть сотни MKV; файлы имеют последовательные метки времени.
- **PASS — реальное удаление по TIME/72h было ранее прямо подтверждено 18.10:** команда `cleanup` удалила **276 истёкших MKV** после `--dry-run`, освободив около **14,9 ГБ**.
- **СИЛЬНОЕ КОСВЕННОЕ ПОДТВЕРЖДЕНИЕ — рабочее удержание примерно 70 часов 21.10:** архив по состоянию соответствует TIME/72h. Старые MKV из предыдущей конфигурации, которые ещё сохранялись при восстановлении 18.10, не видны в начале списка `cam101`. Это согласуется с последующей очисткой.
- **ЕЩЁ НЕ ПОДТВЕРЖДЕНО ОТДЕЛЬНО — именно автоматическое выполнение очистки через Cron в HH:03 после 18.10.** Скриншоты не содержат `LAST CLEANUP` и логов Cron. Нельзя выдавать косвенные признаки за протокол выполнения конкретного задания.

## Безопасная финальная проверка автоматического Cron

На действующем KN-1012 **только чтение**, без запуска `cleanup`:

```sh
sh /opt/etc/nvr-v2.sh status
crontab -l
```

В `status` проверить время и результат `LAST CLEANUP`: если оно позднее ручной очистки 18.10 в 22:00:46 и согласуется с заданиями Cron, можно засчитать **PASS автоматического запуска очистки по расписанию**. Не выполнять ручную очистку ради подтверждения: она сотрёт различие между запусками по расписанию и вручную.

**Не расширять эти результаты на CIRCULAR/HYBRID**: на домашнем роутере они не включались, аппаратную приёмку на отдельном тестовом диске ещё требуется завершить.
