# Keenetic NVR v2.5.0-rc.1 — кандидат выпуска (18.10.2026)

> **Release candidate, не финальный production release.** На настоящих KN-1012 аппаратно проверены NVR TIME/72h и STREAM. Режимы CIRCULAR/HYBRID пока только CI; выпуск `v2.5.0` без суффикса остаётся заблокированным до [#7](https://github.com/saymer-alt/keenetic-nvr/issues/7) и [#10](https://github.com/saymer-alt/keenetic-nvr/issues/10).
>
> Это примечания к **предварительному** выпуску. Тег и GitHub Pre-release публикуются автоматикой **только после успешной проверки `nvr` на `main`**. Наличие документа само по себе релиз не создаёт.

## Функции

- **NVR/v2:** RTSP → MKV без перекодирования, сегменты около 900 секунд, watchdog и почасовая очистка TIME/72h.
- **Storage modes v2.5:** TIME (только после заданного возраста `mtime`), CIRCULAR (по заполнению), HYBRID (по возрасту и заполнению). **CIRCULAR/HYBRID могут удалить раньше заданного срока**.
- **NAND safety:** Entware во внутренней UBIFS, runtime в RAM/tmpfs через KAS `S00ubifs`, архив только на отдельном USB EXT4, storage-guard отказывает при ненадёжном mount.
- **Telegram:** предупреждения и read-only команды `/status`, `/cameras`, `/disk`, `/help`.
- **STREAM/v1:** отдельный RTSP → HTTP MPEG-TS сервис для Selenga и аналогового ТВ без MKV и без cron очистки NVR.

## Перед установкой и обновлением

- **Этот RC предназначен для тестирования**, прежде всего в режиме `TIME/72h` на KN-1012 с отдельным архивным EXT4. Не включайте CIRCULAR/HYBRID на единственной копии важных записей: аппаратная приёмка ещё впереди.
- **Обновление NVR v2.4 → v2.5 автоматическим скриптом не поддерживается** ([#13](https://github.com/saymer-alt/keenetic-nvr/issues/13)); старый upgrade v2.3 → v2.4 для этого не годится.
- **Полный путь установки `setup.sh` на пустом тестовом диске ещё не принят аппаратно**. Восстановление на чистой Entware с существующим архивом выполнялось вручную и описано в [полевом протоколе](FIELD-ACCEPTANCE-2026-10-18.md).
- Никакой автоматической установки или обновления на роутерах при публикации GitHub Release **не выполняется**.

## Ещё НЕ проверено

- CIRCULAR и HYBRID на отдельном тестовом диске, а также сценарии низкого свободного места.
- Autostart STREAM после reboot; повторный reboot NVR на конфигурации после восстановления 18.10; USB-loss/read-only; намеренное отключение самого RTSP-источника; длительный soak-test. Эксплуатационное восстановление записи NVR после reboot и отсутствия FFmpeg-процессов **уже подтверждено 13.10 (3/3)**: [полевой журнал](FIELD-REBOOT-2026-10-13.md).
- Полная установка v2.5 через `setup.sh`/`fresh-install.sh` на пустом архивном EXT4 и автоматический upgrade v2.4→v2.5 (последний не реализован). Развёртывание NVR на чистой Entware вручную **проверено 18.10.2026**; это другой сценарий.
- Подтверждение самого запуска Cron cleanup в HH:03 после восстановления по `LAST CLEANUP`/журналу (21.10 содержимое архива соответствует ~70 часам хранения, но прямого журнала Cron пока нет).
- STREAM: несколько клиентов одного канала не поддерживаются `ffmpeg -listen 1`.

## Как пользоваться

Новая NVR — по [README](README.md), только со специально подготовленным отдельным EXT4 и проверкой `sh -n`; **не запускать fresh-install на уже существующих MKV**. Для такого диска использовать [MESH-RECOVERY](NVR/v2/MESH-RECOVERY.md), без форматирования. Конфиги с паролями и Telegram-токены держать только локально (0600), не публиковать `ps` с RTSP credentials.

STREAM устанавливать **отдельно** по [STREAM/v1/README](STREAM/v1/README.md), использовать [фактически проверенный M3U для Selenga](STREAM/v1/playlist/selenga-sony-1992.m3u).

GitHub Pre-release `v2.5.0-rc.1` привязывается к проверенному CI SHA ветки `main`; ссылка и архив исходников доступны со [страницы Releases](https://github.com/saymer-alt/keenetic-nvr/releases). Публикация **не означает автоматическую установку на работающие роутеры**.
